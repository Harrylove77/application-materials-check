# 对话回执格式

最终回复必须直接给出完整回执，不能只链接receipt.md/PDF或只摘录几条风险。默认不生成回执PDF；材料PDF照常输出。表格前仅简写项目、入学季、查阅日期、总体状态。正文只有两个模块，不加来源附录和技术日志模块。

## 一、材料检查

| 材料 | 要求 / 状态 | 点评与处理 | 对应文件 |
| --- | --- | --- | --- |
| 成绩单及评分说明 | 必交 / 已核对 | 简述姓名、学校、成绩的一致性及实际问题。 | 实际文件名 |
| 英语能力证明 | 必交 / 缺件 | 缺正式报告，CV中的分数不能代替；有其他有效证明时按条件核对。 | 未提供 |
| 个人陈述 | 依项目要求 / 待确认 | 写具体逻辑或名称问题、页码及处理建议。 | 实际文件名 |
| 推荐材料 | 依项目要求 / 状态待核对 | 区分本地文件与系统直传，不将无本地PDF自动判作缺件。 | 实际文件名或渠道说明 |

这是格式示意，不是任何学校的必交清单。实际逐行覆盖本项目本阶段材料，包括已齐、缺件、条件性及相关可选附件，不能只列问题材料或照搬示例必要性。

点评通常1至3句：结论、简短证据位置、具体处理。跨文件矛盾注明双方位置。区分确认冲突、需解释和未核验，不打风格分，不把抽取失败等同于内容错误。技术哈希、逐页映射与解析日志留manifest。重要风险较多可在单元格分点，不能为了简短而漏报。对话中的本地文件链接用实际绝对路径。

## 二、提醒

不用表格，按需列出：
- 【申请阶段】round、截止日期/时间/时区，早轮和最终轮分别列。
- 【申请阶段，若适用】电子IELTS/TOEFL分享、送分对象/代码、推荐人直传及状态核对。
- 【获录取后】最终成绩单、毕业/学位证、认证报告或原件核验。
- 【注册/入学前】offer条件期限、证件有效性与更新。
- 【抵港/到校后】已核实且与项目有关的后续事项。

提醒模块集中展示非附件点评的时间/流程事项，不等同于“录取后才做”。**申请阶段必要的送分未完成仍影响就绪判断**；当前缺英语报告须在表格列缺件，电子分享另在提醒说明。后续阶段材料未到期不混为当前缺件。

仅列适用提醒，附必要官网链接及查阅日期，不堆砌生活建议。官网未给时刻/时区或办理阶段时写待确认，不猜为23:59，不把已完成的直传重复写成未做。

## 数据到对话

requirements、findings.stage：application（默认）、after_offer、registration、post_arrival。后续阶段条目进入提醒，不计当前缺件或高风险阻碍。

requirements.kind：material/workflow。省略时test_agency、online_text、later_stage默认流程，其余默认材料。阶段未知保持申请阶段的保守待确认，不能无依据后移。

requirements.comment保存简洁点评；note、checks、findings保留完整依据。plan.reminders保存title、stage、action，可带due_at、time_zone、condition、source_ids、status；日期、轮次、范围先核实。

scripts/receipt.py生成report/receipt.md底稿。执行者检查分类与点评、清理重复，把核对后的完整内容直接展示在最终对话，不能仅存盘。两模块后只简写输出目录或下载链接。
